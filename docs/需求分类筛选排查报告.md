# 需求信息页分类筛选不显示卡片 — 问题排查报告

> 日期：2026-08-03（第二次修订：定位到真正根因并完成终版修复）
> 状态：已修复（前端本地过滤），已验证

---

## 一、问题现象

用户端「需求信息」页面（`/前端/src/pages/DemandsPage.tsx`）：
- 分类选择「全部」→ 需求卡片正常显示
- 选择具体分类（行业领域 / 应用环节）→ 第一次排查后仍只显示极少数几条

## 二、真正根因

**后端 `GET /api/v1/demands?category=` 是整串精确匹配（`category = 传入值`），不支持模糊/多值；而需求的 category 是「行业维度 + 应用环节维度」的组合字符串，维度筛选在服务端根本无法实现。**

### 2.1 数据形态（实测公网后端，111 条需求）

`demands.category` 为组合格式，且**不统一**：

| 形态 | 示例 | 数量 |
|------|------|------|
| 双维度完整 | `行业领域/智能制造|应用环节/生产制造` | 多数（约 90+ 条） |
| 仅行业维度 | `行业领域/高端装备` | 少量 |
| 空 | `''` | 8 条 |

分类树（`GET /api/v1/categories?type=demand_category&tree=true`）下，行业领域 / 应用环节各有一批子分类，下拉选项与数据中实际使用的子分类名称一致。

### 2.2 后端匹配行为（接口实测）

| 传入 category | 返回条数 | 说明 |
|--------------|---------|------|
| `智能制造` | 0 | 裸名称，匹配不到任何整串 |
| `行业领域/智能制造` | **1** | 只有 1 条 category 恰好等于该整串 |
| `行业领域/高端装备` | 4 | 恰好 4 条单维度记录 |
| `行业领域/智能制造,行业领域/高端装备` | 0 | 不支持逗号多值 |
| `行业领域/智能%` | 0 | 不支持通配符 |

结论：**category 参数只能精确匹配完整字符串**。前端无论传裸名称还是带前缀的子串，都无法覆盖 `行业领域/智能制造|应用环节/xxx` 这类组合记录 —— 这就是「只显示很少几个」的原因（选中「智能制造」只能命中恰好等于该串的 1 条）。

### 2.3 历史原因

2026-07-29 将分类筛选从前端本地 `.filter()` 下沉到后端 `category` 参数（同事实现为整串精确匹配），与前端「维度筛选」的交互语义不匹配，从此该功能即失效。

## 三、修复方案（已实施并验证）

**前端恢复本地过滤：一次拉全量需求，在客户端按「维度前缀/子分类」子串匹配。**

`/前端/src/pages/DemandsPage.tsx` 改动：
1. 新增 `loadAll`：按后端单页上限 50 翻页拉取全部需求（当前 111 条，量级可控）；
2. `filteredDemands`（useMemo）本地过滤：
   - 行业：`category.includes('行业领域/' + 所选)` 
   - 应用环节：`category.includes('应用环节/' + 所选)`
   - 关键词：标题/企业/描述（剔除 source 注释）子串匹配
3. 无限滚动改为客户端切片（每次 +12 条），`total` 显示过滤后数量；
4. 列表缓存（POP 返回恢复）改为缓存全量数据 + 可见条数。

### 验证（用公网后端真实数据模拟前端过滤逻辑）

| 筛选条件 | 修复前（后端精确匹配） | 修复后（本地过滤） |
|---------|---------------------|------------------|
| 全部 | 111 | 111 |
| 行业=智能制造 | 1 | **62** |
| 行业=高端装备 | 4 | 4 |
| 应用=质量检测 | 1 | **18** |
| 应用=生产制造 | 0 | **25** |
| 智能制造+质量检测 | — | **16** |

`tsc -b` 通过，`vite build` 通过，`dist` 已更新（index-B8enQ2Bx.js）。

## 四、后续建议（可选优化，需后端配合）

若后续数据量增长，建议后端将 `category` 参数改为**包含匹配（LIKE %value%）**或**支持多值（IN）**，前端即可恢复服务端分页筛选，减少全量拉取。当前 111 条量级下本地过滤无性能问题。
