## 二、P0 详细说明（优先处理）

### 1. MemoryRouter —— 门户端路由不落 URL

**位置**：`前端/src/main.tsx:30`

```tsx
<MemoryRouter>
  <App />
</MemoryRouter>
```

**问题**：MemoryRouter 把路由状态存在内存里，地址栏 URL 永不变化、刷新页面直接回到首页、无法分享/收藏深链接（如 `/news/123`）、无 SEO 支持。

**注意**：代码里有微信小程序/企微容器检测（`applySafeAreaFix`），若门户只嵌小程序 WebView 则 MemoryRouter 是合理选择。**但当前已作为独立公网站点部署**（`.env.production` 直连公网 API + vite `base: './'`），与部署形态矛盾。

**建议**：确认部署形态——
- 独立公网站点 → 改 `BrowserRouter`（需 Nginx 配置 history fallback）或 `HashRouter`（零配置，URL 带 #）
- 仅小程序内嵌 → 保持现状，忽略此项

### 2. 首页视频 40.6MB

**位置**：`前端/public/assets/video/video.mp4`

**问题**：首页 `<video>` 加载 40.6MB 视频，poster 也 800KB。移动端流量杀手，弱网下首屏体验差。

**建议**：
- 视频转码压缩（1080p → 720p、H.264、码率控制在 ~2Mbps）
- 或改封面图 + 点击后加载视频
- 视频移出 public，走对象存储/CDN，加懒加载

### 3. 列表接口全量返回（与后端联动）

**详见**：《新闻动态加载慢排查报告.md》——列表接口不裁字段（content 全文 + base64 封面全量返回），门户端一次拉 18 条 ≈ 26MB。

**建议**：后端列表接口 `.Select()` 剔除 content；新增公开详情接口 `GET /api/v1/news/{id}`；封面/正文图改存 URL 走 CDN。

## 三、P1 详细说明

### 4. kimi 调试插件无条件进生产

**位置**：`前端/vite.config.ts:6`

```ts
plugins: [inspectAttr(), react()]
```

**问题**：`kimi-plugin-inspect-react` 无环境判断，`vite build` 生产包也会注入调试插件。

**建议**：改为仅开发模式启用：

```ts
plugins: [
  ...(process.env.NODE_ENV === 'development' ? [inspectAttr()] : []),
  react(),
]
```

### 5. 管理端三个列表页「全量拉取 + 前端分页」

**位置**：
- `admin-frontend/src/pages/news/NewsList.tsx:49-67`
- `admin-frontend/src/pages/companies/CompanyList.tsx:52-71`
- `admin-frontend/src/pages/demands/DemandList.tsx:62-81`

**问题**：注释明确写着"后端单页有上限，循环翻页取尽全部，再交给前端分页展示"。`while(true)` + `page_size=50` 把所有数据拉完。当前数据量小可跑，但会随数据量线性劣化。

**建议**：改真服务端分页（submissions 三页已是正确范式，可参考 `DemandSubmissionList.tsx`）。

### 6. reorder 硬编码 company_id

**位置**：`admin-frontend/src/pages/news/NewsList.tsx:75`

```ts
await api.put('/admin/news/reorder', { company_id: 1, ids: list.map((item) => item.id) })
```

`demands/DemandList.tsx:86` 同样问题。`company_id: 1` 明显是从 CompanyEditor 复制残留，应删除（看后端 `ReorderNews(req.IDs)` 只收 ids）。

## 四、P2 详细说明

### 7. wangeditor 粘贴图片仍走 base64

**位置**：`admin-frontend/src/components/RichEditor.tsx`

**问题**：只配了 `uploadImage.customUpload`（点上传按钮 → URL），但**直接 Ctrl+V 粘贴图片时 wangeditor 默认仍会 base64 内嵌**——这是数据库 base64 数据膨胀的另一半来源。

**建议**：配置 `pasteImage` 拦截，粘贴图片转为上传换取 URL：

```ts
MENU_CONF: {
  pasteImage: {
    async customPaste(clipboardEvent, insertFn) {
      const files = Array.from(clipboardEvent.clipboardData?.files ?? [])
      for (const file of files) {
        const res = await uploadFile(file)
        if (res?.url) insertFn(res.url, res.file_name || '', res.url)
      }
    },
  },
}
```

### 8. Dashboard 拉 200 条 intents 客户端过滤

**位置**：`admin-frontend/src/pages/Dashboard.tsx:34`

```ts
api.get('/admin/intents?page=1&page_size=200').catch(() => null)
```

**建议**：后端支持 status 过滤参数，或增加待处理数量统计接口。

### 9. 登录硬编码用户信息

**位置**：`admin-frontend/src/pages/Login.tsx:25`

```ts
auth.setAuth(data.access_token, { id: 0, username: form.username, role: 'admin' })
```

**建议**：登录后调 `/admin/me` 获取真实用户信息；或后端在登录响应里带用户字段。

### 10. 门户端 fetchDemands 全量 + isHtmlContent 误判

**位置**：
- `前端/src/lib/services.ts:245`：`page_size: 10000` 拉全量需求
- `前端/src/lib/utils.ts:12`：`/<\/?[a-z][\s\S]*>/i` 会把含 `<` 的纯文本误判为 HTML

## 五、P3 详细说明

### 11-12. 硬编码颜色与内联样式

机械扫描结果：

| 项 | 管理端 | 门户端 |
|----|:---:|:---:|
| 硬编码 hex | 25 | 24 |
| 硬编码 rgb/rgba | 10 | 32 |
| 内联样式 | 161 | 18 |
| Tailwind 色类 | 0 | 80 |

高频硬编码色（管理端）：`#999`×18、`#1677ff`×14、`#d9d9d9`×6、`#52c41a`×4、`#ff4d4f`×4。建议收敛为 antd/主题 CSS 变量。

### 13. 门户端 53 个 shadcn 组件只用 1 个

**位置**：`前端/src/components/ui/`（53 个文件）

**问题**：业务代码实际只用 `popover`（2 处 import）。其余 52 个（chart/calendar/command/form 等）是 shadcn init 时全量生成的死代码。

**建议**：删除未用组件文件（保留 popover 及其依赖如 button/dialog），或保留等后续功能扩展（记录在案即可）。

### 14. 表单附件上限 100MB 与后端错位

**位置**：`前端/src/pages/DemandFormPage.tsx:7`、`SolutionFormPage.tsx:7`

```ts
const MAX_FILE_SIZE = 100 * 1024 * 1024; // 100MB
```

**建议**：与后端上传限制对齐（确认 `/api/v1/demand-submissions` 的实际大小限制），否则前端放行、后端拒收。
