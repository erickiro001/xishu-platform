# 需求管理列表显示条数受限排查报告

> 排查日期：2026-08-05
> 结论：**后端单页上限 50 条，非 99**。管理后台需求列表最多显示 50 条。

---

## 一、问题描述

用户反馈后台管理「需求管理」列表显示条数疑似被限制在 99 个。

## 二、前端代码核查（admin-frontend）

`src/pages/demands/DemandList.tsx`：

- 请求参数：`page=1&page_size=10000`（`pageSize = 10000`）
- 表格配置：`pagination={false}`，一次性渲染后端返回的所有行
- 本地仅有状态筛选（`filtered` computed），**无任何条数截断逻辑**

**结论：前端不存在 99 条限制**，显示条数完全取决于后端接口返回多少条。

## 三、后端接口实测

### 3.1 公网后端（生产）`https://xishu-online.api.show.linktwins.com`

| 请求 | 返回 list 长度 | total |
|------|--------------|-------|
| `GET /api/v1/demands?page=1&page_size=10000` | **50** | 110 |
| `GET /api/v1/demands?page=1&page_size=200` | **50** | 110 |
| `GET /api/v1/demands?page=2&page_size=10000` | 50 | 110 |

→ **`page_size` 无论传多大，每页最多返回 50 条**；分页取第 2 页可拿到其余数据，说明是分页上限而非总数限制。

### 3.2 局域网后端（开发）`http://192.168.3.39:23357`

- `GET /api/v1/demands?page=1&page_size=10000` → 返回 5 条 / total 5（开发环境数据量小，未触发上限）

### 3.3 项目内既有记录佐证

- `前端/src/pages/DemandsPage.tsx:69`：注释「后端单页上限 50，翻页取尽全部需求」
- `前端/src/lib/services.ts:276/320`：注释「后端无单条公开详情接口，循环翻页查找（后端单页上限 50 条）」
- `docs/需求分类筛选排查报告.md:51`：注释「按后端单页上限 50 翻页拉取全部需求（当前 111 条，量级可控）」

## 四、结论

1. **需求管理列表确实被限制显示，但上限是 50 条/页，不是 99**。
2. 限制来自**后端分页接口的单页上限**（Go 后端，`/api/v1/demands` 实测；`/admin/demands` 管理端接口需登录态未直接实测，但同一后端分页实现，几乎可确定同样受限）。
3. 管理后台列表页只请求第 1 页且无分页器，因此当需求总数超过 50 时，列表只显示前 50 条。

## 五、建议方案

### 方案 A（已实施 ✅）：管理端循环翻页取尽 + 前端分页

已按此方案改造 `admin-frontend` 三个列表页（`DemandList.tsx` / `CompanyList.tsx` / `NewsList.tsx`，2026-08-05）：

```ts
// 后端单页上限 50，循环翻页取尽全部需求
const all: DemandItem[] = []
let p = 1
while (true) {
  const data = await api.get(`/admin/demands?page=${p}&page_size=50${query}`)
  all.push(...data.list)
  if (p * 50 >= data.total || data.list.length === 0) break
  p++
}
items.value = all
```

- 列表页加分页器：每页 50 条，`showTotal` 显示总条数。
- 分页后上移/下移/拖拽的索引换算为全量索引（`(page-1)*50 + index`），排序功能不受影响。
- 优点：不动后端，需求总数 100+ 量级可控，一次全量拉取后本地筛选/排序逻辑不受影响。
- 注意：需求量大后首屏加载会变慢，可后续再加「本地虚拟滚动/分批渲染」。

### 方案 B：后端放开 `page_size` 上限

后端（Go 服务，不在本工作区）将单页上限从 50 提高，或对管理端接口放开限制。需后端同事配合，且对大页查询有性能考量，不建议调太大。

### 方案 C：管理端增加真分页

列表页加 antd Table 分页器，按页请求后端。改动量最大，且与现有「拖拽排序全量列表」交互冲突，不推荐。

## 六、影响范围

- **需求管理**（`DemandList.tsx`）：必然受影响（公开接口已实测 50 条上限）。
- **新闻动态**（`NewsList.tsx`）、**企业管理**（`CompanyList.tsx`）：同样请求 `page_size=10000`，同一后端分页实现，预计同样被限制在 50 条，如需可一并排查确认。
