# 「最新动态」加载慢排查报告

> 排查日期：2026-08-03
> 排查对象：用户端前端（`前端/`）
> 结论：**用户判断正确——前端确实一次性拉取全部动态，且每条都携带完整详情正文（含 base64 内嵌大图），导致每次加载要下载约 26MB 数据。**

---

## 一、实测证据（生产后端 https://xishu-online.api.show.linktwins.com）

`GET /api/v1/news?page=1&page_size=5` 实测：

| 指标 | 数值 |
|------|------|
| 响应体大小 | **7,323,716 字节（约 7.3MB）**，仅 5 条 |
| 请求耗时 | 2.2s（公网，还只是 5 条） |
| 新闻总数 | 18 条 |
| 全量拉取预估 | 18 条 ≈ **26MB** |

单条记录字段体量（核心问题）：

| id | content 长度 | 说明 |
|----|-------------|------|
| 31 | 999,969 字符 | 富文本 HTML 内嵌 base64 图片 |
| 30 | 656,373 字符 | 同上 |
| 16 | 1,430,532 字符 | 同上 |
| 22 | 2,384,046 字符 | 同上 |
| 23 | 687,849 字符 | 同上 |

- `content` 是完整富文本正文，**图片以 `data:image/webp;base64,...` 直接内嵌在 HTML 中**（管理端 wangeditor 编辑器写库时的存储形态）。
- `cover_image` 同样是 **base64 字符串**（每条约 100KB~360KB）。
- `summary` 字段为空字符串，前端列表摘要只能靠前端 `stripHtml(content)` 截取兜底。

## 二、前端三个页面的实际加载行为

| 页面 | 代码 | 行为 | 下载量 |
|------|------|------|--------|
| 首页「最新动态」 | `HomePage.tsx` → `fetchArticles()` | `page_size=10000` **一次性拉全量** | ≈ 26MB |
| 全部动态页 | `AllNewsPage.tsx` → `fetchArticlesPage(1, 20)` | 总量 18 < 20，**一次请求就拉完所有动态** | ≈ 26MB |
| 新闻详情页 | `NewsDetailPage.tsx` → `fetchArticle(id)` | 无单条公开详情接口，**循环翻页拿全量后在本地 find**（每页 50 条，18 条一次拿全） | ≈ 26MB |

> 三个页面虽然代码上都有"分页"逻辑，但因总量仅 18 条，实际每次都把全部 18 条动态（含全部正文+内嵌图）一次性下载下来。这就是"一次性读取了所有的动态以及详情页的内容"。

## 三、根因

1. **后端列表接口（`GET /api/v1/news`）不做字段裁剪**：列表场景根本用不到 `content` 全文，却每条原样返回 65 万~238 万字符的富文本正文，且封面图为 base64 内联（无法走 CDN 缓存、体积放大 ~33%）。
2. **公开端缺少单条详情接口**：管理端有 `GET /admin/news/:id`，但公开端没有 `/api/v1/news/{id}`，前端详情页只能翻页全拉再本地查找。
3. 前端受限于以上两点，无法从自身减少传输量（仅能减少拉取条数）。

## 四、修复建议

### 前端可立即做（治标，降下载量 2/3 以上）

1. **首页**：`fetchArticles` 改为只取前 6 条（`fetchArticlesPage(1, 6)`），首页卡片仅展示 3 条 → 下载量从 26MB 降到约 9MB（后续需后端裁剪字段才能真正轻量）。
2. **全部动态页**：`PAGE_SIZE` 从 20 调小（如 6），配合现有无限滚动按需翻页 → 首屏只下载 6 条，滚动加载更多。
3. 详情页前端无法优化，等后端加详情接口。

### 后端配合（治本，需与后端同事对齐）

1. **列表接口支持字段裁剪**（如 `?fields=id,title,summary,cover_image,published_at` 或 `?exclude=content`），列表返回摘要而非全文；若 `summary` 为空，由后端在列表接口生成摘要。
2. **封面图/正文图改存静态 URL**（图片走对象存储/CDN），不再以 base64 入库返回——体积可再降 ~90%。
3. **新增公开单条详情接口** `GET /api/v1/news/{id}`，详情页一次请求即可，不再翻页全拉。
